# ADR-0009: 原始资料与提取产物禁入库，并以阻断式检查执行

- **状态**：accepted
- **日期**：2026-11-12
- **决策者**：用户（人类责任方）要求把“PDF 原文与成段摘录不得进 git”立为硬纪律，不能只写在说明里，要有阻断机制；执行方落地条款、检查器与钩子
- **serves_charter**：服务于 C3（来源封闭、可追溯）与 C6（可机械检查、可审计）
- **grounding_refs**：无（治理决策）
- **affected_files**：`CONSTITUTION.md`（新增第 13 条、第 5 条保护清单）、`AGENTS.md`（新增第 7bis 条、目录树）、`.gitignore`、`scripts/check_no_raw_material.py`（新建）、`scripts/README.md`、`.githooks/pre-commit`（新建）、`ERRATA.md`（若发现既有违规）、`CHANGELOG.md` 批次 0016

## 背景

本仓库为公开仓库，同时需要以本地 PDF 作为来源核验依据（`resources/pm/`，位于仓库之外）。两者存在结构性冲突：核验需要看到原文，公开仓库又不得承载原文。仅靠“说明里写一句不要提交”无法防止误操作——`git add .`、临时把提取文本放进仓库、把整页 OCR 结果粘进 Markdown，都是可预期的失误路径，且一旦进入历史就难以撤回。

`CONSTITUTION.md` 第 2 条管的是“来源是否合法”，没有管“核验证据以什么形态存放”。这个缺口在批次 0015（按本地 PDF 核对来源）中第一次变得现实：该批次产生了六份 PDF 的全文转储与 OCR 输出。

## 决定

1. **在 `CONSTITUTION.md` 新增第 13 条**：禁止入库原始资料（PDF/EPUB/扫描件等）、提取产物（文本层转储、OCR 全文、逐页转录）、成段原文摘录，以及任何可替代原作的实质内容；允许页码定位、来源标识与单条不超过一行或一句并附出处的最短引证。检查失败即阻断提交。
2. **把第 13 条列入第 5 条保护清单**，使其不能被普通修订降低强度。
3. **在 `AGENTS.md` 新增第 7bis 条执行纪律**：提取产物固定落在仓库外临时目录；`resources/` 永不 `git add`；提交前运行检查器或启用钩子；发现违规按“页码 + 自述摘要”替换并登记 ERRATA，不静默删除。
4. **扩展 `.gitignore`**：覆盖文档/二进制扩展名与常见提取产物命名，作为第一道防线。
5. **新增阻断式检查器** `scripts/check_no_raw_material.py`：扫描**已跟踪文件**，按扩展名、体积、OCR 转储特征（超长引文、页码序列、PDF 提取乱码/点线）判定；命中即非零退出。
6. **接入 pre-commit**：仓库内提供 `.githooks/pre-commit`，通过 `git config core.hooksPath .githooks` 启用；钩子只调用该检查器。若部署环境不允许钩子，等价命令写入 `scripts/README.md` 与 `AGENTS.md`。

## 结果

- 误提交在本地被拦截，而非在公开仓库暴露后补救。
- 代价：提交前多一次秒级扫描；`.gitignore` 的宽扩展名规则可能挡住合法的图片资产——当前仓库无此需求，若将来需要，必须走 ADR 并给该路径显式豁免，而不是删规则。
- 未处理：已存在于历史的违规内容。本决策只约束新提交；历史清理是独立决策。
