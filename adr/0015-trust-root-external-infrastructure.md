# ADR-0015: 信任根无法在仓库内自保——停止加门，M2 关闭受阻于外部基础设施

- **状态**：`proposed`（2026-11-14）
- **日期**：2026-11-14
- **决策者**：架构负责人（按用户批准执行）；人类责任方已批准方向
- **serves_charter**：C3（来源封闭、可追溯）、C6（可机械检查、可审计）的维护条件
- **grounding_refs**：无（决策针对验证机制本身，不依赖来源条目）
- **affected_files**：`ROADMAP.md`（M2 出口 1/5/7、残余风险与状态）、`GAP_LEDGER.md`（关闭依据改为外部引用）、`AGENTS.md` 3.6.6、`scripts/check_gap_ledger.py`、`validation/reviews/2026-11-14-d8bf413-review.md`、`CHANGELOG.md`

## 1. 问题：每加一道门，就多一个仓库内的信任根

ADR-0014 把验证链能机械化的部分做成显式留痕：检查器哈希、规格区段指纹、验收快照漂移检测、缺口关闭依据字段。它同时写明这些绑定**不能自证**。后续复核（基线 `48128a8`）暴露了同一个结构的递归性质：

| 新增的“门” | 谁保护它 | 保护它的人是否与被保护者同源 |
|---|---|---|
| `checker-pins.json` | 它自己登记的哈希 | 是——同一工作区、同一写权限 |
| 复核转录件（`validation/reviews/*.md`） | `check_spec_pins.py` 的字段检查 | 是——执行方可以写任意内容 |
| 根检查器 `checker.py` | `check_checker_pins.py`，后者又在 `checker-pins.json` 内 | 是——同一次 `--write` 可让两者自洽 |
| `.githooks/pre-commit` | 可被 `--no-verify` 跳过，也可被改 `core.hooksPath` | 是——本机无强制执行环境 |

结论：**仓库内部不存在一个“门”能保护自己之外的信任根。** 每新增一道门，只是把信任根从 A 移到 B，B 仍然在同一方手里。继续加门会把“验证链自证”问题从一层扩展到 N 层，而检测能力不增加。

本轮六项实现修正（枚举非法值参与 `aggregate()`、`node_type`/`assumption.status`/`assertion.assumption` 的确定结论、堵住空负例豁免、G-016 组数更正）已证明：这些是**实现层面可修**的问题，修完可以用固定正负例守住。它们与上面那个结构问题不同层：前者是“判定是否忠实”，后者是“谁来判定判定者”。

## 2. 决定

### 2.1 停止新增门禁

不再为“验证验证者”新增检查器、绑定文件或哈希层。已存在的四道绑定（检查器哈希、规格指纹、快照漂移、关闭依据字段）保留，因为它们降低了**误操作**与**静默修改**的概率；但它们不被当作“验证权分离”的证据。

新门禁的准入条件收紧为：只有能被**仓库外**机制承接的，才允许新增。仓库内自证的，一律不加。

### 2.2 关闭依据外置

`GAP_LEDGER.md` 的 `关闭依据` 列只接受外部产物引用：

```
外部复核：<路径>；sha256：<64 位小写十六进制>；基线：<提交号>
```

- 路径可以是仓库外路径（如 `/tmp/...`），由执行方登记，复核方下一轮核对哈希。
- `validation/reviews/` 下的转录件降级为历史记录，文件头注明“非权威、不构成关闭依据”；AGENTS.md 3.6.6 明确“复核结论不得由执行方转录为依据”。
- `scripts/check_gap_ledger.py` 机械核对路径存在、是文件、sha256 一致、字段齐全；`--self-test` 的 E01–E05 固定正负例（路径不存在、哈希不符、伪造路径指向目录、缺 sha256 必须报错）。

**哈希能证明什么、不能证明什么**：它能证明“复核方下一轮读到的文件与执行方登记时一致”，不能证明复核真实发生、也不能证明复核方独立。这一限制是本 ADR 的立论基础，不当作缺陷隐藏。

### 2.3 M2 关闭受阻于外部基础设施，暂不关闭

`ROADMAP.md` 的 M2 出口 5 改为“受阻于外部基础设施，暂不关闭”。具体地：

- 出口 1–4、6–7 仍可满足，且应继续满足；
- 出口 5 的 `open=0` 只说明台账字段齐备，**不构成关闭依据**；
- M2 的“实质收敛”判决需要三个本机不具备的条件：真 CI 在受保护分支上执行验证、受保护分支禁止直接推送、复核方独立持有工具链与提交权限。三者缺一，M2 不关闭。

### 2.4 G-014 重开

G-014 的原关闭依据建立在“入口枚举短路是有意设计”之上，而该短路违反 A.2 的 `fail > cannot_evaluate > pass` 与顺序无关性。本轮选择“枚举非法值作为子句结果参与 `aggregate()`”，G-014 从 `closed` 改回 `open`；修好实现后仍需外部复核才能关闭。

## 3. 考虑过的选项

| 选项 | 为什么不选 |
|---|---|
| 继续加门（保护 `checker-pins.json`、保护转录件、保护根检查器） | 递归不收敛；每层都能被同一写权限方同改；检测力不增，维护面线性增长 |
| 删除全部绑定，回到“人工评审” | 丢掉已获得的“静默修改变显式留痕”，误操作成本上升 |
| 引入外部 CI 作为唯一验证点 | 方向正确，但本机不具备该基础设施，属于外部依赖而非本轮可执行动作 |
| 只改文档、不改台账格式 | 转录件仍可被引用为关闭依据，结构问题原样保留 |

## 4. 后果

**正向**：

- 停止在无收益的递归上加门，把精力放回可修的实现缺陷与内容条目；
- 关闭依据的格式使“执行方转录”与“复核方产物”物理分离，下一轮复核有明确的核对对象（路径 + 哈希）；
- M2 的状态从“一直差一点”变为“明确受阻”，避免用 `open=0` 冒充收敛。

**负向**：

- M2 在外部条件具备前不会关闭，v1.0.0 的关键路径因此挂起；
- 外部路径（`/tmp/...`）不随仓库分发，克隆者无法自行核对历史关闭依据的哈希，只能核对“登记值存在”；
- 每次关闭缺口都要多一份外部产物与哈希登记，操作成本上升。

## 5. 边界与残余风险

1. **执行方可以伪造路径与哈希**：机器只核对“文件在、哈希对”，不能核对“这份文件真是复核方写的”。
2. **复核方可以与被执行方共谋**：机器无法识别独立性，只能靠外部组织安排。
3. **`/tmp` 会消失**：外部产物不在版本控制内，跨机器、跨时间不可复现；本 ADR 接受这一代价，换取“不把转录件当权威”。
4. **停止加门不等于现状安全**：已登记的关闭依据仍然只在“字段齐备”层面成立，实质收敛仍需外部复核。
