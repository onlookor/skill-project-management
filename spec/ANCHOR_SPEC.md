# 锚点与引用规范

**状态**：normative。本文件规定本仓库内交叉引用（锚点）的合法形态、解析规则与失效处置。
**依据**：ADR-0007。**对齐对象**：`/home/wgz/projects/skills/software-engineering/锚点与引用规范.md` 与 `ADR-ANCHOR-01`（稳定地址化、行号禁用、指纹只作漂移检测、失效显式报错）。
**执行**：`scripts/check_anchors.py`。规范与脚本冲突时以本文件为准，脚本修订。

## 1. 术语

- **锚点（anchor）**：指向另一处权威内容的显式引用。
- **稳定 ID**：跨编辑不改变的定位键——规则号、`check_id`、来源 `id`、术语 `term_id`、方法号、TODO 编号、ADR 编号。
- **标题路径**：`doc:<path>#sec-<标题>`，按目标文件的标题逐字匹配。
- **指纹（fingerprint）**：被锚定文本块的规范化哈希，只用于检测“内容是否被改动”，**不用于定位**。
- **展示行号**：解析器在运行时从文件现算出的行号，只用于人眼定位与报错信息，**不写入任何权威文件**。

## 2. 允许的锚点形态

| 类别 | 形态 | 解析目标 | 失效条件 |
|---|---|---|---|
| 规则 | `G-A1`、`rule:G-A1` | `GRAMMAR.md` 的规则标题 `**G-A1（…）**` | 规则被删或改名 |
| 检查项 | `check:<check_id>` | `spec/methods/deterministic-checker.md` 附录 A 或 `validation/CHECKLIST.md` | 检查项被删或改名 |
| 知识条目 | `knowledge:<term>` | `knowledge/anchored-entries.jsonl` 的 `term` | 条目被删或改名 |
| 方法 | `method:M-EST-01` | `knowledge/methods/registry-skeleton.md` 的 `method_id` | 方法被删或改名 |
| 来源 | `source:<id>`，或 `grounding_ref` 中的裸 `id` | `SOURCE_LEDGER.md` 的 `#### <id>` | 条目被删（ADR-0005 后删除即失效） |
| 术语 | `T-A-001`、`term:T-A-001`、`GLOSSARY.md#T-A-001` | `GLOSSARY.md` 的术语标题 `**T-A-001 <名称>**` | 术语被删或改号 |
| 待办 | `T-113`、`todo:T-113` | `TODO.md` 的行首编号 | 条目被删（按纪律不得删除，只能标 `[done]`/`[dropped]`） |
| ADR | `ADR-0007`、`adr:0007` | `adr/0007-*.md` | 文件被删或改号 |
| 标题路径 | `doc:GRAMMAR.md#sec-规则组 A：项目存在的充要条件` | 目标文件内逐字唯一的标题 | 标题被改字 |
| 条款号 | `doc:CONSTITUTION.md#clause-12.3` | `第 12.3 条` 标题或加粗子条款 | 条款被删或改号 |
| 章节引用 | `` `CONSTITUTION.md` 第 2.6 条 ``、`` `AGENTS.md` 第 3.1 条 `` | 目标文件的条款/小节编号 | 目标文件不存在、编号不存在、同名文件歧义 |

**章节引用为什么合法**：章节号是结构地址，不是物理地址。在文件中插入一行不会改变 `第 2.6 条` 的解析结果；只有重编号才会失效，而重编号本身就是需要登记的实质变更。

**外部资料的页码定位**：`SOURCE_LEDGER.md` 的核验状态可以用“印刷页 N / PDF 第 N 页”标注外部文献中的论据位置。这类页码**不是仓库锚点**，不参与 `scripts/check_anchors.py` 解析，也不得用于指代本仓库任何文件；它只服务于“该结论从哪一页得到”的可复核性。外部文献无稳定结构地址，页码是唯一可用的定位粒度，因此不适用第 3 条的禁令范围。

## 3. 禁止的形态

1. **行号 locator**：`file.md:123`、`file.md:45-49`、`#L123`、`@m:123`、`第 123 行`。行号随插入/删除整体位移，不能承担定位。
2. **以“第一个匹配”兜底**：解析到 0 个目标必须报错；解析到 ≥2 个必须报歧义；不得静默取首个。
3. **把展示行号写入权威文件**：任何 Markdown/JSONL/脚本中的权威引用不得包含行号。

**唯一例外（as-of 证据）**：`adr/`、`CHANGELOG.md`、`ERRATA.md` 中记录历史时点的行号可保留，但必须显式声明“行号指该决策/批次时的版本”。这类引用按冻结证据处理，检测器只输出提示，不计错误。

## 4. 解析与失败语义

检测器 `scripts/check_anchors.py` 的结论是封闭枚举：

| 代码 | 级别 | 含义 |
|---|---|---|
| `E-FILE-MISSING` | 错误 | 引用的目标文件不存在（排除通配与占位符） |
| `E-NO-TARGET` | 错误 | 稳定 ID / 条款号 / 标题路径在目标文件中不存在 |
| `E-AMBIGUOUS` | 错误 | 目标不唯一（同名文件、重复标题、重复编号） |
| `E-LINE-LOCATOR` | 错误 | 活跃文件中出现行号 locator |
| `W-FINGERPRINT-DRIFT` | 警告 | 被锚定文本块的指纹与基线不一致，需人工复核 |
| `I-AS-OF` | 提示 | 冻结文件中的行号证据，按 as-of 保留 |

退出码：`0` 通过（可有警告/提示）；`1` 存在错误；`2` 仓库结构或基线无法解析。

**显式失败原则**：锚点解析失败必须让检查失败，不得降级为“跳过”或“按文件名猜”。宁可报错，不可指向错误条文。

## 5. 指纹与基线

- **覆盖范围**：`GRAMMAR.md` 的每条规则块（`rule:G-*`）与 `SOURCE_LEDGER.md` 的每个来源条目块（`source:<id>`）。这两类是被引用最多的锚点，且改动会直接影响规则语义。
- **规范化**：逐行 `strip()`，丢弃空行，行内连续空白折叠为单个空格，以 `\n` 连接。
- **算法**：`sha256`。选型理由：标准库可用、无碰撞风险、对空白与换行不敏感；不引入 Markdown AST 依赖，避免解析器差异成为新的失效源。
- **基线**：`scripts/anchor_baseline.json`，记录每个锚点的 `path`、`heading`、`sha256`。
- **重冻流程**：故意修改规则/来源 → 审阅 `git diff` → 运行 `python3 scripts/check_anchors.py --write-baseline` → 基线变更与内容变更同批提交。
- **指纹的边界**：指纹只回答“这块文本变了吗”，不回答“改得对不对”。它不能替代人工审阅，也不能用于定位。

## 6. 与软工既有口径的关系

**相同**：稳定地址化；行号不得作 locator；指纹只作漂移检测；失效显式报错；冻结文件按 as-of 保留。

**不同**：本仓库**不引入** `@m:` / `@d:` 前缀语法。现有引用已经是可读的稳定 ID（`G-A1`、`check_id`、`term_id`、来源 `id`）或章节号，共 236 处；改写为 `@` 语法没有定位收益，只会制造迁移风险。若未来需要**行内**机器锚点（同一段落内多个锚点、需精确到列表项/表行），直接采用软工的 `@` 语法与 `sec-`/`row-`/`li-` 子锚，不另造第二套。

## 7. 维护流程

1. 新增规则、来源、术语、方法、检查项时，先分配稳定 ID，再在引用处使用该 ID。
2. 任何实质性变更后运行 `python3 scripts/check_anchors.py`；错误必须清零，警告必须逐条说明。
3. 规则/来源内容被有意修改时，按第 5 节重冻基线，并在 `CHANGELOG.md` 同一批次说明。
4. 新增文件引用一律写仓库相对路径；禁止写绝对路径与行号。
